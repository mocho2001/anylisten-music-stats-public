# 配置说明

Any Listen Music Stats 设计为**零配置即可使用**。本文档说明可调整的行为与高级用法。

## 默认行为（无需配置）

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 统计阈值 | 30 秒 | 连续播放 ≥30 秒计为“有效播放” |
| 会话最大保留 | 20,000 条 | 超过自动截断最旧记录 |
| 数据版本 | v2 | 自动兼容 v1 迁移 |
| 统计对象 | 所有播放 | 包含本地文件、在线流媒体（宿主支持的所有来源） |

---

## 可通过代码调整的参数（需重新构建）

> ⚠️ 修改以下参数需要编辑源码并重新构建扩展包，普通用户**无需**关注。

### 核心统计参数 (`plugin/src/index.ts`)

```typescript
// 第 14 行：有效播放阈值（毫秒）
const THRESHOLD = 30_000;  // 30 秒

// 第 15 行：最大会话记录数
const MAX_SESSIONS = 20_000;
```

| 参数 | 建议范围 | 影响 |
|------|----------|------|
| `THRESHOLD` | 10,000 - 60,000 | 过短会把试听计入统计；过长会漏记短歌 |
| `MAX_SESSIONS` | 5,000 - 50,000 | 过大增加内存/存储占用；过小丢失历史 |

**修改示例**：
```typescript
// 改为 20 秒阈值，保留 50000 条会话
const THRESHOLD = 20_000;
const MAX_SESSIONS = 50_000;
```

## 运行时可调整行为（面板操作）

### 时间范围筛选（Dashboard 面板）
- **全部**：显示所有历史数据
- **今天**：本地日期 00:00 - 23:59
- **本周**：本周一 00:00 - 周日 23:59
- **本月**：本月 1 号 00:00 - 最后一天 23:59
- **今年**：本年 1 月 1 日 - 12 月 31 日

### 排序方式（排行榜标签页）
- **按次数**：播放次数降序
- **按时长**：累计收听时长降序

## 数据管理操作（面板“数据管理”标签页）

### JSON 备份
导出完整统计数据（tracks + sessions + 元数据），包含版本号，可用于迁移、备份。

### JSON 恢复（覆盖）
**⚠️ 破坏性操作**：完全替换当前所有数据为导入文件内容。
- 会在导入前自动创建 `pre-import-<时间戳>.json` 备份
- 仅接受本扩展导出的标准格式

### JSON 合并
智能合并导入数据到现有数据：
- **tracks**：以复合键（`key|id|name|singer`）去重，保留播放时长较大者
- **sessions**：以 `key|startedAt|endedAt|seconds` 去重，保留时间跨度较大者
- **元数据**：以导入文件为准（版本号、导出时间等）

### CSV 导出
导出会话明细表，字段：
```
key, songId, songName, artist, album, startedAt, endedAt, durationSeconds, source
```
- `startedAt/endedAt`：ISO 8601 本地时间
- `durationSeconds`：整数秒
- `source`：播放来源标识

### 重置所有数据
**⚠️ 极度危险**：彻底清空 tracks、sessions、统计汇总。
- 需在输入框手动输入 `RESET` 确认
- 操作不可撤销，建议先做 JSON 备份

## 宿主补丁配置（仅开发者关注）

当前稳定基线适配 **Any Listen 0.10.1-beta.5**。

如需适配新版本宿主，请参考：
- `docs/development/VERSION_WORKFLOW.md` - 版本工作流规范
- `host-patch/README.md` - 补丁脚本说明
- `host-patch/patch_host.py` - 核心补丁逻辑

**关键补丁点**：
1. Player API 暴露（`api.player`）
2. Dashboard iframe 注入与消息桥接
3. 播放事件钩子（play、pause、musicChanged、ended 等）

## 常见调整场景

| 场景 | 建议方案 |
|------|----------|
| 想统计更短的试听 | 源码改 `THRESHOLD = 15_000` 并重新构建 |
| 保留更多历史记录 | 源码改 `MAX_SESSIONS = 50_000` 并重新构建 |
| 迁移到新电脑 | JSON 备份 → 新机器 JSON 恢复（覆盖） |
| 合并手机/电脑数据 | 先备份，再用 JSON 合并功能 |
| 导出数据做外部分析 | CSV 导出 → Excel/Python/Pandas 处理 |
| 清理异常数据 | 导出 JSON → 手工编辑 → JSON 恢复（覆盖） |
