# 数据与隐私

本文档说明 Any Listen Music Stats 如何处理你的听歌数据，以及你的隐私权利。

---

## 核心原则

> **你的听歌数据，完全属于你。**
>
> - 所有数据**仅存储在你的本地电脑上**
> - 插件**不发起任何网络请求**，不上传、不同步、不分析、不画像
> - 无账号系统，无云端存储，无第三方追踪
> - 你拥有数据的**完全控制权**：随时查看、导出、备份、删除

## 数据存储位置

```
%APPDATA%\Any Listen\music-stats\
├── data-v2.json          # 当前主数据文件（v2 格式）
├── data-v1.json          # 旧版数据（兼容迁移用，可删除）
├── pre-import-*.json     # 导入前自动备份（时间戳命名）
```

- 使用 Any Listen 提供的 `api.storage` 接口，隔离于其他扩展
- 文件权限跟随用户账户，其他用户无法读取

## 隐私保护措施

| 措施 | 实现方式 |
|------|----------|
| **零网络通信** | 插件代码中无 `fetch`、`XMLHttpRequest`、`WebSocket`、Electron `net` 等网络 API 调用 |
| **本地隔离** | 使用 Any Listen `api.storage` 命名空间隔离，不共享给其他扩展 |
| **无遥测** | 无任何用量统计、错误上报、特征上传代码 |
| **无标识符** | 不生成、不存储、不发送任何设备指纹、用户 ID、广告 ID |
| **数据最小化** | 仅记录统计必需字段，不记录歌词、封面、播放进度细节、音量、均衡器等 |
| **用户控制** | 所有导入/导出/合并/重置操作需用户在面板主动触发 |

## 你的权利

| 权利 | 实现方式 |
|------|----------|
| **知情权** | 本文档完整披露数据范围、存储位置、处理逻辑 |
| **访问权** | 面板实时显示所有聚合数据；JSON 导出获取完整原始数据 |
| **携带权** | JSON/CSV 导出为标准格式，可迁移到任何工具 |
| **删除权** | 面板“重置”功能一键清空；或手动删除 `music-stats` 文件夹 |
| **更正权** | JSON 导出 → 手工编辑 → JSON 恢复（覆盖） |
| **限制处理权** | 卸载扩展即停止一切数据处理，历史数据保留由你决定 |

## 数据保留与清理

| 策略 | 说明 |
|------|------|
| **会话上限** | 20,000 条（FIFO，超限自动删除最旧） |
| **聚合数据** | 无上限，随播放自然增长 |
| **自动备份** | JSON 导入/合并前自动创建 `pre-import-<时间戳>.json` |
| **手动备份** | 建议定期 JSON 导出到异地（U盘、网盘、NAS） |
| **卸载保留** | 卸载扩展**不删除**数据文件，重装自动恢复 |

## 常见疑问

**Q: 听歌数据会上传到 Any Listen 官方吗？**
A: **绝不会**。插件运行在 Any Listen 进程内，但仅使用宿主提供的本地存储 API，不经过宿主服务器。

**Q: 插件作者能看到我的数据吗？**
A: **不能**。插件无网络代码，数据从未离开你的电脑。

**Q: 重装系统后数据怎么办？**
A: 提前做 JSON 备份（或直接复制 `%APPDATA%\Any Listen\music-stats\` 文件夹），重装后恢复即可。

**Q: 会记录我听歌的具体时间点吗？**
A: 会记录每次有效播放的开始/结束时间戳（毫秒精度），这是生成“收听日历”“趋势图”等功能所必需的。你可通过 CSV 导出查看完整明细。

**Q: 能否关闭会话明细记录，只保留聚合统计？**
A: 当前版本不支持分别开关，会话明细用于去重合并和日历/趋势功能。如需极致精简，可定期导出 JSON 后在面板重置，仅保留聚合数据。
