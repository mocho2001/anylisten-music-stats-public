# 兼容性说明

本文档记录 Any Listen Music Stats 的宿主版本适配情况、已知限制与跨版本行为差异。

---

## 宿主版本适配矩阵

| Any Listen 版本 | Music Stats 版本 | 适配状态 | 备注 |
|-----------------|------------------|----------|------|
| **0.10.1-beta.5** | **v10** | ✅ **稳定基线** | 当前唯一官方支持版本，用户实测验收通过 |
| 0.10.x (其他 beta) | - | ❌ 未测试 | 接口可能不兼容 |
| 0.9.x | - | ❌ 不支持 | 扩展 API 架构差异大 |
| 1.x (正式版) | - | 🟡 规划中 | 待官方发布后按工作流适配 |
| macOS / Linux 版 | - | ❌ 不支持 | 仅适配 Windows 版 |

> **关键原则**：仅发布经**用户实机测试验收通过**的适配版本。未验收版本不提供下载。

---

## 核心依赖接口

Music Stats 依赖以下 Any Listen 扩展 API，这些接口在 0.10.1-beta.5 中可用：

| API | 用途 | 兼容性风险 |
|-----|------|------------|
| `api.player` | 获取播放器实例 | 🔴 高 - 宿主内部重构易变 |
| `api.player.getCurrentTrack()` | 当前轨道信息 | 🟡 中 - 返回结构可能变 |
| `api.player.getPlaybackState()` | 播放状态 | 🟢 低 - 枚举值稳定 |
| `api.player.on/off()` | 事件监听 | 🔴 高 - 事件名/参数可能变 |
| `api.storage.get/set()` | 本地存储 | 🟢 低 - 标准 KV 接口 |
| `api.commands.register()` | 注册命令 | 🟢 低 - 标准扩展机制 |
| `api.commands.execute()` | 执行命令 | 🟢 低 |
| `api.ui.addMenuItem()` | 添加菜单项 | 🟡 中 - UI API 可能调整 |
| `api.ui.showPanel()` | 显示面板 | 🟡 中 |

## 宿主补丁依赖点

补丁修改的 `app.asar` 内部位置（0.10.1-beta.5 基准）：

| 补丁点 | 所在模块 | 变更类型 | 升级风险 |
|--------|----------|----------|----------|
| Player API 注入 | 扩展 API 初始化 | 新增导出 | 🔴 极高 - 核心架构变动 |
| Dashboard iframe 注入 | 设置页面路由/菜单 | DOM 注入 | 🔴 高 - UI 重构易失效 |
| 消息桥接注册 | 窗口消息处理 | 事件监听器 | 🟡 中 - 通信机制相对稳定 |
| 协议拦截 (`als-dashboard://`) | 协议处理器 | 新增处理器 | 🟡 中 |

> **升级时必须**：获取新版 `app.asar` → 完整差异审计 → 逐点评估补丁存活性 → 重写失效补丁。

## 数据格式兼容性

### Store v2 (当前)
```json
{
  "version": 2,
  "tracks": { "key": { ... } },
  "sessions": [ { ... } ],
  "totalSeconds": 123456,
  "validPlays": 789
}
```
- ✅ 向前兼容：v10 可读取 v1 数据并自动迁移
- ✅ 向后兼容：未来版本承诺提供迁移工具

### Store v1 (历史)
```json
{
  "tracks": [ { ... } ],  // 数组格式
  "sessions": { "key": [ ... ] }  // 对象格式
}
```
- v10 启动时自动检测并迁移为 v2
- 迁移过程：数组→对象、对象→数组、字段补全、去重

### 导入兼容策略
`normalizeImportedStore()` 支持：
- tracks：数组 / 对象 双格式
- sessions：数组 / 对象 双格式
- 缺失字段：默认值兜底
- 类型异常：强制转换 + 阈值过滤

## 已知限制

| 限制 | 影响 | 规划改进 |
|------|------|----------|
| 仅支持 Windows | macOS/Linux 用户不可用 | 待宿主跨平台扩展 API 统一 |
| 单宿主版本适配 | 宿主更新即失效 | 建立自动化差异检测流程 |
| 无云同步 | 多设备数据需手动合并 | 规划本地网络同步（可选） |
| 会话上限 2万条 | 极重度用户会丢失早期明细 | 可配置上限 + 归档机制 |
| Dashboard 无分页 | TOP 100 固定、历史列表全量渲染 | 虚拟列表/分页 |
| 无图表导出 | 趋势/日历仅能截图 | 规划 PNG/PDF 导出 |
| 无多用户隔离 | 同一 Windows 用户共享数据 | 宿主不支持多用户，无法解决 |

## 迁移指南（给开发者）

### 从 v1 迁移到 v2
自动完成，无需手工操作。迁移代码在 `plugin/src/index.ts` 的 `normalizeImportedStore()` 中。

### 适配新宿主版本
参考 `docs/development/VERSION_WORKFLOW.md` 完整流程。

关键检查点：
1. `api.player` 是否存在、接口签名是否变化
2. 设置页面 DOM 结构、菜单注册方式是否变化
3. `postMessage` 通信机制是否受 CSP/安全策略影响
4. `asar` 解包/重打包工具链是否兼容新版 Electron

- [ ] 重启 Any Listen，正在播放的歌继续统计
- [ ] Dashboard 所有标签页（概览/排行/日历/历史/趋势/数据管理）正常切换

- [ ] CSV 导出打开无乱码、字段完整
