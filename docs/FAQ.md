# 常见问题 (FAQ)

## 安装与启动

### Q1: 安装后在扩展列表看不到 Music Stats？
**A:** 请确认：
1. Any Listen 版本为 **0.10.1-beta.5**（当前稳定基线适配版本）
2. 安装 `.alix` 后重启一次 Any Listen
3. 在设置 → 扩展 中检查是否显示“Music Stats”，如显示“已禁用”请点击启用

### Q2: 提示“扩展包签名无效”怎么办？
**A:** 当前稳定基线发布的 `.alix` 包已由维护者签名。如果你下载的是官方 Release 页面的文件却提示签名无效，可能是下载损坏，请重新下载。如果是自行构建，请检查 `.env` 中的 `PRI_KEY` 与 `PUB_KEY` 是否成对、格式正确。

### Q3: 点击“打开面板”或设置菜单的“听歌统计”没反应/白屏？
**A:** 这通常是**宿主版本不匹配**导致。当前 v10 仅适配 **Any Listen 0.10.1-beta.5**。其他版本（如 1.x、0.9.x、0.11.x）暂不支持，请等待对应适配版本发布。

## 统计规则

### Q4: 播放了歌曲但统计面板没变化？
**A:** 请检查：
- 是否**连续播放同一首歌 ≥ 30 秒**？（暂停、切歌、缓冲时间不计入）
- 面板是否需要刷新？（切换标签页或重新打开面板）
- 是否在“今天/本周/本月/今年”筛选下查看？（默认显示“全部”）

### Q5: 为什么阈值是 30 秒？能改吗？
**A:** 30 秒是业界常见的“有效播放”门槛，用于过滤试听、误触、缓冲等非真实收听行为。
- **普通用户**：无法通过界面修改，这是统一规则，保证数据可比性。
- **开发者**：可修改 `plugin/src/index.ts` 中的 `THRESHOLD` 常量并重新构建。

### Q6: 暂停播放时计时会停止吗？
**A:** 是的。统计逻辑：
- `play` 事件 → 开始计时
- `pause` / `stop` / `buffering` → 暂停计时，记录已播放时长
- `play` 恢复 → 继续计时
- `musicChanged` / `ended` → 结束本会话，若累计 ≥30秒则写入统计

### Q7: 切歌时上一首没播满 30 秒会记录吗？
**A:** **不会**。切歌触发 `musicChanged`，若累计播放 < 30 秒，该会话被丢弃，不计入任何统计。

### Q8: 重启 Any Listen 后，正在播放的歌会被记录吗？
**A:** 会。插件启动时会同步当前播放状态（`api.player.getCurrentTrack()` + `getPlaybackState()`），若正在播放则开始计时；关闭软件时会在 `beforeunload` 保存当前会话进度。

## 数据管理

### Q9: JSON 备份、恢复、合并有什么区别？
| 操作 | 行为 | 适用场景 |
|------|------|----------|
| **备份** | 导出完整数据副本 | 定期异地备份、迁移电脑 |
| **恢复（覆盖）** | **完全替换**当前数据为导入文件 | 换新电脑、回滚到某个备份点 ⚠️破坏性 |
| **合并** | 智能去重合并导入数据到现有数据 | 多设备数据汇总、误删后补回、合并手机/电脑数据 |

### Q10: 合并会产生重复数据吗？
**A:** 不会。合并逻辑：
- **Tracks**：以复合键 `key|id|name|singer` 去重，保留 `totalSeconds` 较大者
- **Sessions**：以 `key|startedAt|endedAt|seconds` 四字段去重，保留时间跨度较大者
- 导入文件格式必须符合本扩展导出标准

### Q11: 能导入其他播放器的数据（如网易云、Spotify）吗？
**A:** **不能直接导入**。本扩展只识别自己导出的 JSON 格式。如需迁移，需编写脚本将外部数据转换为本扩展的 `data-v2.json` 结构（参考 `plugin/src/index.ts` 中的 `normalizeImportedStore`）。

### Q12: CSV 导出的时间是 UTC 还是本地时间？
**A:** **本地时间**（ISO 8601 格式，含时区偏移，如 `2024-01-15T20:30:45+08:00`）。Excel 直接打开即可正确显示。

### Q13: 误触“重置”清空了数据能恢复吗？
**A:** 重置前**无自动备份**。但：
- 若之前做过 JSON 备份 → 用“恢复（覆盖）”找回
- 若导入/合并过 → 检查 `music-stats/` 下的 `pre-import-<时间戳>.json` 自动备份
- 否则**不可恢复**。请养成定期 JSON 备份习惯。

## 兼容性与更新

### Q14: 支持 Any Listen 1.x / 正式版吗？
**A:** 当前 v10 **仅适配 0.10.1-beta.5**。新版本宿主发布后，维护者会按《版本工作流规范》进行差异审计、补丁迁移、实测验收，通过后发布对应适配版本。请关注 Release 页面。

### Q15: 更新扩展会丢失统计数据吗？
**A:** **不会**。扩展更新只替换代码逻辑，数据文件 `data-v2.json` 独立存储在 `%APPDATA%\Any Listen\music-stats\`，不受扩展安装/卸载/更新影响。

### Q16: 为什么不发布适配最新 Any Listen 版本的包？
**A:** 遵循**“用户实测验收通过才发布”**原则。新宿主版本发布后，需要：
1. 获取原始 app.asar
2. 与 v10 基线差异审计
3. 制定最小补丁迁移方案
4. 代码质量检查
5. **用户实机测试通过**
只有第 5 步完成才会发布。这保证你拿到的包是稳定可用的。

### Q17: 会支持 macOS / Linux 版 Any Listen 吗？
**A:** 目前仅适配 **Windows 版 Any Listen**。跨平台支持取决于宿主扩展机制的一致性，暂无计划。

## 功能与界面

### Q18: Dashboard 里的“收听日历”颜色代表什么？
**A:** 颜色深浅表示当天收听时长：
- 无色 = 无收听
- 浅色 = 少量收听（< 1 小时）
- 中等 = 中等收听（1-3 小时）
- 深色 = 大量收听（> 3 小时）
具体分段可在源码 `renderCalendar()` 中查看。

### Q19: TOP 100 只显示 100 首，能看更多吗？
**A:** 当前界面固定显示 TOP 100。如需完整数据，请使用 **JSON 备份** 导出完整 tracks 列表，或 **CSV 导出** 获取所有会话明细。

### Q20: 能按专辑/歌手/年份等维度统计吗？
**A:** 当前版本提供：
- 歌曲 TOP 100
- 歌手 TOP 100
- 专辑 TOP 100
更多维度（年代、流派、自定义标签等）规划中，欢迎在 Issues 提建议。

### Q21: 界面语言能切换英文吗？
**A:** 当前仅简体中文。如需多语言，欢迎贡献 PR（涉及 Dashboard HTML/JS 字符串提取）。

## 故障排查

### Q22: 面板打开报错/控制台有红字怎么办？
**A:** 请收集以下信息在 Issues 反馈：
1. Any Listen 版本
2. Windows 版本
3. 面板打开方式（设置菜单 / 扩展卡片 / 快捷键）
4. 开发者工具 Console 报错全文（F12 打开）
5. 最近一次成功播放的时间

### Q23: 统计数据突然变少/归零了？
**A:** 可能原因：
- 手动点了“重置”
- JSON “恢复（覆盖）”导入了旧/空文件
- `data-v2.json` 文件损坏（极少见）
排查：检查 `music-stats/` 下是否有 `pre-import-*.json` 备份，尝试恢复。

### Q24: 导入 JSON 后提示“文件无效”？
**A:** 检查导入文件：
- 是否为本扩展导出的标准 JSON（含 `version: 2`、`tracks`、`sessions` 字段）
- 是否被文本编辑器保存时改了编码（需 UTF-8）
- 文件大小是否异常（过大可能损坏，过小可能不完整）
